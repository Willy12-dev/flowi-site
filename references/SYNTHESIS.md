# Carousel format library — synthesis

Distilled from ~193 reference images across @ugwusmate, @adam.hafner, @thedigital.indian,
@mrsocialgrowthstudio_, Hina Arora, BRAND BY SID, Evolving AI, @sifuyik,
therapist channels, trader-letter accounts, single-poster financial infographics, and
~15 other niche-specific creators.

## The DNA shared by every high-converting carousel

1. **One concept per slide.** Never two. Body text never exceeds ~50 words on body slides.
2. **Visual rhythm** — slides 01 cover → 02-N body → final CTA. 5–9 slides standard. 9 is the upper limit before drop-off.
3. **Slide marker.** Top corner shows `01/09` or `SLIDE 01 / 09`. Bottom shows handle + page dots.
4. **One color accent.** A single non-neutral color, used sparingly (5–10% of pixels). Italic accent word/phrase is the most universal device.
5. **Hook on cover.** Curiosity-gap title with a contrarian or specific claim. Always concrete numbers when possible ("$6,783 revenue", "120 prompt codes", "8 strategies").
6. **CTA mechanic.** Almost always "Comment WORD" to trigger a DM. Sometimes "save this" or "follow @handle". Never bare links on the slide.
7. **PS line.** Premium creators sign off with a handwritten PS at the bottom — feels human, anti-AI.

## Multi-platform pack — what each carousel ships as

Every `POST /api/carousel/zip` produces a single zip containing:

```
<spec.id>/
├── READ_ME_FIRST.md       ← what's here + recommended posting order
├── spec.json              ← source of truth, edit + regenerate
├── 01-cover.png ... NN     ← 1080×1350 PNGs for IG + Pinterest
├── caption.txt            ← Instagram caption (paste-ready)
└── posts/
    ├── twitter-thread.md  ← X thread split per tweet, char-counted
    ├── reddit.md          ← long-form Markdown + recommended subs
    ├── quora.md           ← Q&A-framed long answer + question prompt
    ├── tiktok-script.md   ← 60–90s talking-head script with beats
    └── pinterest-pins.md  ← per-pin title + description (SEO-tuned)
```

All variants generate deterministically from `spec.json` — edit the spec once,
regenerate, and every platform stays in sync.

## The image-asset layer — prompts for everything

Every visual asset the system can use has a paste-ready prompt in
`content/prompts.json`. The user generates the image externally (ChatGPT
image-gen / Gemini Imagen / Midjourney / Flux), drops it into the listed
path under `public/images/`, and the system picks it up.

### What's covered

| Asset class | Where used | Default size | Style |
|---|---|---|---|
| `carousel-photo` | PhotoFrame slide background | 1080×1350 | editorial-cream |
| `blog-hero` | Blog article hero + PDF cover | 1600×900 | editorial-cream / premium-dark / cream |
| `pdf-cover` | Field-guide / bundle PDF cover page | 1200×1600 | editorial-cream |
| `course-cover` | Gumroad product thumbnail | 1080×1080 | courseware-cover |
| `social-banner` | X header, Pinterest board cover | 1500×500 / 1000×1500 | per vertical |
| `youtube-thumb` | TikTok / YouTube Short cover | 1080×1920 | premium-dark |
| `avatar` | FakeTweet slide avatar | 400×400 | editorial-cream |

### Where the prompts come from

- **Per-spec auto-resolution:** every `photo-frame` slide in a CarouselSpec
  yields one resolved prompt in `IMAGE_PROMPTS.md` (inside the deck zip).
  Slide-level overrides (`promptTemplate`, `promptVars`) let any deck pull
  in a specific style without changing the registry.
- **Hub at `/admin/prompts`:** one-click copy of any template, with inline
  variable editing. Use this for blog heroes, PDF covers, course covers,
  social banners — anything not bound to a single carousel.

### Workflow

1. **Carousel-tied images:** generate the zip → open `IMAGE_PROMPTS.md` →
   copy the prompt for each photo-frame slide → generate the image → save
   to the listed path → set `bgImage` on that slide in `spec.json` →
   regenerate the zip. The image now bakes into the rendered PNG.
2. **Standalone images** (blog hero, PDF cover, course cover, X header):
   visit `/admin/prompts` → copy the prompt from the right template card →
   generate → save to the listed path. No spec required.

### Adding a new asset class

Edit `content/prompts.json`:

```json
{
  "templates": [
    {
      "id": "my-new-asset",
      "title": "...",
      "asset_class": "...",
      "asset_path": "public/images/...",
      "size": "WxH",
      "aspect": "...",
      "style_default": "editorial-cream-photography",
      "prompt_template": "{style.base}\n\n... use {VARIABLE} ... \n\n{style.negative}",
      "variables": [{ "name": "VARIABLE", "default": "..." }]
    }
  ]
}
```

The hub picks it up on next load — no code change required.

## The monetization layer — courses + topic library

The carousel system isn't the product. The **courses** are. Every carousel funnels into a course (the primary CTA), and every long-form export (Reddit, Quora) mentions a bigger product (the secondary route — FlowiAI Trader / Woyuduin / Agent Memory book).

### Files
- `content/courses.json` — registry of all live + waitlist + planned courses. Each entry maps `topics` strings to a slug, status, price, and CTA mechanic. **Edit this once → propagates to every carousel's exports.**
- `content/topic-library.json` — backlog of 35+ carousel ideas. Each entry has a hook, italic accent, format hint, status (`planned` → `drafted` → `posted`).

### Daily-pack workflow (5 posts/day across all platforms)

```bash
# 1. Draft 5 carousels from the topic library (random pick across verticals)
node scripts/draft-daily-pack.mjs --count 5

# Or target a specific vertical / topic:
node scripts/draft-daily-pack.mjs --count 3 --vertical ai_builder
node scripts/draft-daily-pack.mjs --topic claude --topic chatgpt

# 2. The drafter writes stub specs to content/carousel-specs/<date>-<topic>.json
# Open each and fill the [bracketed placeholders] with real copy

# 3. In /admin/studio: paste the spec → preview → download deck
# Each deck = 5–9 PNGs + caption + Twitter/Reddit/Quora/TikTok/Pinterest exports

# 4. Post to each platform manually (system doesn't auto-post)
# 5. Mark the topic as "posted" in topic-library.json
```
